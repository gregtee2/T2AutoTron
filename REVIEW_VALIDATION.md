## Remaining source work / release blockers

1. **A complete command gateway still does not exist.** Final-dispatch ownership/cancellation/freshness checks are not proven across every direct-device/audio path. A Stop cannot undo I/O already issued by a node, and a hung node can retain the lifecycle queue. Nested device lifecycle/reconciliation and cross-boundary buffer semantics need broader coverage. Do not describe these as universally enforced.
2. **Whole-project browser behavior remains unverified.** Nested navigation replaces the live canvas; full execution continuity, disposal during navigation, all control dirty events, undo/redo, failed-import rollback, multi-tab command ownership, and large-graph reload without localStorage require browser-level tests. Close-time delivery is best-effort, not guaranteed. Revision conflict UX must let users safely export/reload/resolve conflicts.
3. **Plugin readiness work remains outstanding.** [PluginLoader.js](v3_migration/frontend/src/registries/PluginLoader.js) still counts script downloads rather than verified registrations; [00_SharedLogicLoader.js](v3_migration/backend/plugins/00_SharedLogicLoader.js) still has an unawaited asynchronous load and separate URL handling. CI's Vite build does not execute runtime-loaded plugins; the added VM tests cover subgraphs only.
4. **Shutdown and health are not fully coordinated.** The server must drain actual engine work, managers, cameras, sockets, and the now-awaitable log writers before exiting. Fatal exception continuation remains in [server.js](v3_migration/backend/src/server.js). Main HA handshake timeouts are implemented, but ongoing dead-connection ping/pong supervision and media reconnect consolidation remain incomplete.
5. **Security hardening is not complete.** A predictable default application PIN remains if none is configured; login throttling/default-credential setup, all discovery target/range validation, public static media access, and credential redaction in out-of-scope worker/discovery logs still require a dedicated audit. Direct authenticated browser camera/image transport needs end-to-end verification.
6. **Persistence guarantees have limits.** Writes are serialized within one process. Named and last-active files are separate atomic replacements, not one transaction; failures are explicitly reported. There is no last-known-good revision history/recovery workflow yet. Symlink checks cannot prevent filesystem races by another local process. File sync does not guarantee portable directory/power-loss durability.
7. **Logs already above their limits need manual archival before restart.** The bounded writer fails closed with `ELOGSIZE` to avoid deleting historical records. It exposes counters/status rather than retrying potentially partial disk writes. Log health is exported by the logger but is not yet fully surfaced in the UI. No real user log was archived/deleted by this review.
8. **Release provenance remains incomplete.** [Dockerfile](home-assistant-addons/t2autotron/Dockerfile) still clones moving remote `stable`; it does not build these uncommitted changes. Base image and source are not immutable pins. Lockfiles and new helpers/tests currently appear as untracked files, despite being unignored; they must be deliberately staged with actual implementation files when a release is authorized. Do not invent a source tag or publish changes during review.
9. **Pi/resource acceptance gates remain outstanding.** Explicit camera byte/FPS/worker budgets, full Node 22 add-on architecture builds, approved HA restart/ingress tests, and the 72-hour Pi soak have not run. The review does not establish production RAM/CPU/disk stability.
