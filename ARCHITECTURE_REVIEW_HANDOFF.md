## What’s working well

- **The product's core direction is sound.** A browser editor with a headless fallback does not require replacing Rete, Express, or JSON files.
- **Shared pure calculations are the right extraction boundary.** Preserve and extend this layer, rather than forcing React UI and backend execution into one enormous node definition.
- **Important device-safety behavior exists.** Generic-device intent is recorded before browser-priority suppression, and HSV-only changes check whether lights are actually on. There are focused regressions in [v3_migration/backend/tests/HAGenericDeviceNode.test.js](v3_migration/backend/tests/HAGenericDeviceNode.test.js).
- **The bulk-state cache already deduplicates concurrent reads** with `fetchPromise` and has an abort deadline. A 2-second TTL means approximately 30 successful full-state refreshes/minute under continuous demand, not one request per node per tick. Do not discard this optimization based on inflated request estimates.
- **Useful observability foundations exist:** intent-versus-reality auditing, command history, node outputs, event lists, status indicators, and bounded in-memory command history.
- **Some security foundations are already present:** masked settings, constant-time PIN comparison, settings allowlisting, Joi schemas, and guarded mutations. The problem is inconsistent coverage and trust decisions, not complete absence of security.
- **The editor already includes useful product features:** favorites, grouping/backdrops, typed sockets, validation/repair on load/import, viewport persistence, performance mode, tooltips, and error boundaries. Improve these instead of rebuilding them.
- **Deployment already separates durable add-on graph storage from application files.** Extend the same convention to all mutable configuration and recovery state.

## Problems found (severity: P0/P1/P2)

Severity meanings: **P0 = must fix before an exposed/released deployment; P1 = must fix for dependable automation and persistence; P2 = should improve, usually after correctness.** Feature ideas are separately marked “nice later.” Security findings are verified source paths, not a claim that a deployed system has been exploited.

**F01 — P0: add-on mode bypasses authentication even on direct network access; camera credentials are returned publicly.**

- [v3_migration/backend/src/api/middleware/requireLocalOrPin.js](v3_migration/backend/src/api/middleware/requireLocalOrPin.js#L44-L48) returns `next()` for **every** add-on HTTP request, without proving it arrived through HA ingress. [home-assistant-addons/t2autotron/config.yaml](home-assistant-addons/t2autotron/config.yaml#L13-L24) enables host networking and direct port 3000; [v3_migration/backend/src/server.js](v3_migration/backend/src/server.js#L1414-L1416) defaults to all-interface binding. An accessible LAN client can reach settings/device mutations outside HA authentication.
- The unguarded camera list returns `cameraConfig.cameras` directly, while the camera mutation stores `password` on each object: [v3_migration/backend/src/api/cameras.js](v3_migration/backend/src/api/cameras.js#L111-L165). Masking only `defaultCredentials` does not mask individual camera passwords. Snapshot routes also expose images without this guard.
- Socket authentication separately trusts broad private-address prefixes; HTTP and Socket.IO have divergent policy. `ip.endsWith('::1')` is not an exact loopback check. Settings are mounted before the later API limiter/security middleware, and the default PIN is predictable: [v3_migration/backend/src/api/middleware/authMiddleware.js](v3_migration/backend/src/api/middleware/authMiddleware.js#L8-L35), [v3_migration/backend/src/server.js](v3_migration/backend/src/server.js#L1197-L1220).
- **Fix:** one tested trust policy for HTTP/socket ingress versus direct access; authenticated/redacted camera and private graph/config reads; exact IP handling; authenticated direct access with setup-time credentials, login throttling, and appropriate transport protection. Retain legitimate ingress use without demanding an extra PIN there. Do not replace the bypass with trust in arbitrary forwarded headers.

**F02 — P0: configuration values cross shell-execution boundaries.**

- [v3_migration/backend/src/api/routes/settingsRoutes.js](v3_migration/backend/src/api/routes/settingsRoutes.js#L139-L155) removes newlines but writes unquoted setting values. [home-assistant-addons/t2autotron/run.sh](home-assistant-addons/t2autotron/run.sh#L71-L78) then **sources** that file as a shell program. Newline removal does not neutralize shell expansion or command syntax. Ordinary spaces/special characters can also break startup.
- [v3_migration/backend/src/api/cameras.js](v3_migration/backend/src/api/cameras.js#L243-L259) interpolates stored camera credentials and URLs into `execSync` shell text. These values originate in writable camera configuration. F01 increases exposure; authenticated configuration is still data, not executable code.
- The same snapshot path can block the automation event loop for up to ten seconds **per attempted URL**; multiple fallback URLs are tried serially.
- **Fix:** parse settings as data in Node, never source them; use asynchronous shell-free process arguments or a maintained digest-auth HTTP implementation; constrain targets, sizes, concurrency, and deadlines; protect discovery endpoints. Test special characters as literal data, not by executing attack payloads on the host.

**F03 — P1: overlapping ticks, destructive reloads, and incomplete node teardown.**

- [v3_migration/backend/src/engine/BackendEngine.js](v3_migration/backend/src/engine/BackendEngine.js#L449-L503) awaits node operations, but [its scheduler](v3_migration/backend/src/engine/BackendEngine.js#L599-L647) launches a new tick every 100 ms without awaiting the previous one. A slow HA call permits overlapping mutation of node state and outputs.
- `stop()` only clears future scheduling. `loadGraphData()` clears maps immediately, does not wait for in-flight work, and never calls old nodes' `destroy()`. The isolated probe showed old tick output reappearing after replacement.
- [v3_migration/backend/src/engine/nodes/DelayNode.js](v3_migration/backend/src/engine/nodes/DelayNode.js#L167-L199) starts repeat/schedule timers during restoration and provides cleanup methods that the engine does not call. Repeated graph reloads can retain old instances/timers.
- The upcoming-events registry survives replacement. This is a **stale display/metadata defect**; the registry itself does not execute schedules, so it is not evidence that its entries fire old device commands.
- [v3_migration/backend/src/api/engineSocketHandlers.js](v3_migration/backend/src/api/engineSocketHandlers.js#L151-L175) monkey-patches `engine.start()` without returning/awaiting the original promise. Callers may announce completion before reconciliation finishes.
- **Fix:** single-flight execution, graph-generation fencing, cancellable bounded I/O, transactional activation, explicit lifecycle, and real engine events instead of method replacement. Preserve the 100 ms nominal cadence initially; do not simply parallelize every node.

**F04 — P1: the intended browser-priority contract is not enforced uniformly.**

- The generic device's command path checks ownership, but [HAServiceCallNode and HALightControlNode](v3_migration/backend/src/engine/nodes/HADeviceNodes.js#L580-L764) issue direct fetches without that guard. A mocked service call executed while browser ownership was active.
- [Heartbeat expiry](v3_migration/backend/src/engine/BackendEngine.js#L210-L236) directly sets `frontendActive = false`; it does not invoke the transition path that reloads/synchronizes/resets HSV. A subsequent heartbeat cannot reactivate it because `frontendHeartbeat()` updates only an already-active frontend. Browser heartbeat cadence is exactly the 30-second expiration boundary: [v3_migration/frontend/src/App.jsx](v3_migration/frontend/src/App.jsx#L545-L551).
- [forceHsvResync and HA synchronization](v3_migration/backend/src/engine/BackendEngine.js#L143-L196) test `node.type === 'HAGenericDeviceNode'`, but [the generic constructor](v3_migration/backend/src/engine/nodes/HADeviceNodes.js#L773-L800) and engine instantiation do not assign that field. The sync code additionally expects `properties.devices`, while the node uses `selectedDeviceIds`, and reads HA state without unwrapping `{ success, state }`.
- [onFrontendInactive](v3_migration/backend/src/engine/BackendEngine.js#L104-L131) reads a hard-coded local graph directory, ignoring the add-on's `GRAPH_SAVE_PATH`. It ignores an empty saved graph. It also resumes/reloads asynchronously without a complete command barrier.
- **Fix:** a shared ownership coordinator plus a command gateway applied to every effect-producing backend node and browser-origin command. Use stable node identity, one handoff transition, the shared graph store, correct HA response normalization, and explicit client/revision acknowledgement. Keep browser precedence and the **30-second timeout** unchanged.

**F05 — P1: graph identity, validation, and activation are too permissive.**

- [Serialization](v3_migration/frontend/src/Editor.jsx#L559-L587) normally writes outer `id/label/position/data`; type identity is often inferred from a mutable display label. Subgraph serialization uses a different property/position layout. No canonical schema version or project revision is written by these paths.
- [Backend loading](v3_migration/backend/src/engine/BackendEngine.js#L262-L349) discards the old graph before validating the new one, accepts multiple property shapes, skips unknown/failed types with logs, and still stores their edges. Duplicate IDs overwrite `Map` entries. The route can report successful loading of a partial graph.
- [Dependency ordering](v3_migration/backend/src/engine/BackendEngine.js#L380-L441) does not report cycles. Its visited set prevents infinite DFS recursion, but cyclic graphs get order-dependent current/prior-tick values rather than defined feedback semantics. Every Receiver depends on every Sender, including unrelated buffers.
- A concrete identity bug: [v3_migration/backend/src/engine/BackendNodeRegistry.js](v3_migration/backend/src/engine/BackendNodeRegistry.js#L162-L169) maps the label `Watchdog` to `CounterNode`, although a real `WatchdogNode` is registered in [v3_migration/backend/src/engine/nodes/UtilityNodes.js](v3_migration/backend/src/engine/nodes/UtilityNodes.js). A label-resolved watchdog can therefore become a counter when loaded headlessly.
- Frontend validation **does exist and is called**. However, [v3_migration/frontend/src/utils/graphValidation.js](v3_migration/frontend/src/utils/graphValidation.js) does not validate port existence, registered types, nested graphs, cycles, or property schemas. Some malformed non-array inputs can cause its validation code itself to throw. Repair can remove data; it is not a substitute for safe activation.
- **Fix:** versioned document codec, explicit type IDs/aliases, shared structural validation plus registry/port checks, recoverable unknown-node placeholders, cycle diagnostics, and validate/compile before swapping the running graph. Distinguish intentionally UI-only nodes from missing executable nodes.

**F06 — P1: subgraphs are exposed as a functioning feature but both executors are placeholders; navigation can lose or mis-save work.**

- [Browser SubGraphNode.data()](v3_migration/backend/plugins/SubGraphNode.js#L145-L170) passes through the trigger and explicitly leaves internal evaluation as a TODO.
- [Backend SubGraphNode.process()](v3_migration/backend/src/engine/nodes/SubGraphNode.js#L30-L86) also contains a TODO. It expects a registry argument the engine does not pass; its internal instantiation does not use the normal restore contract.
- [Editor subgraph navigation](v3_migration/frontend/src/Editor.jsx#L2745-L2860) replaces the editor's current nodes with the child graph. Save/autosave/close serialization reads those current nodes, not a composed root document. Saving while inside can replace the root last-active graph with just the child. `exitToMainGraph()` explicitly restores an earlier snapshot without saving all nested changes.
- Exposed port keys are based on node-array positions (`in_${idx}`/`out_${idx}`), so unrelated insertion/reordering can change external connection identities.
- **Fix now:** visible unsupported-execution warnings and prevent unsafe activation/conversion/save paths without deleting existing documents. **Then:** root-document-preserving navigation, stable port IDs, and tested nested execution through the same compiler/runtime contracts. Do not add more nested-graph features before this works.

**F07 — P1: persistence and autosave can claim success while losing automation changes.**

- [Server graph saves](v3_migration/backend/src/api/routes/engineRoutes.js#L541-L697) write directly to final files, including last-active state. There is no temp-write/atomic replacement, serialized writer, revision conflict detection, or last-known-good recovery. Power loss or competing saves can truncate/overwrite usable state. Save success and runtime activation success are conflated or reported incompletely.
- The `graphName` load path has some sanitization, but the supplied `graphPath` branch remains unrestricted: [v3_migration/backend/src/api/routes/engineRoutes.js](v3_migration/backend/src/api/routes/engineRoutes.js#L170-L206). Socket graph loading likewise accepts a path. All entry points need the same graph-store boundary.
- [Autosave](v3_migration/frontend/src/Editor.jsx#L3220-L3311) marks dirty only for node/edge creation/removal, not ordinary property edits or moves. Server save is nested inside a localStorage size condition, so documents at/above roughly two million serialized characters do not autosave to the server. Dirty state is cleared and a success toast shown without checking the HTTP save result.
- [Close/visibility sync](v3_migration/frontend/src/App.jsx#L16-L58) uses synchronous XHR, drops the ingress prefix, supplies no PIN, hardcodes localhost for a Vite page, and excludes empty graphs. It then announces inactivity even after failure. Browser close is not a dependable last chance to transmit a large document.
- [Camera configuration](v3_migration/backend/src/api/cameras.js#L35-L55) is written inside the application tree rather than `/data`, and write errors are swallowed before API success. Settings writes are also direct-file writes.
- **Fix:** one durable graph/config store, revisioned acknowledged autosave independent of localStorage, one ingress/auth-aware client, root-document serialization, and explicit saved-versus-active revisions. Empty graphs are valid persisted state; they must not resurrect old automations.

**F08 — P1: HA connection health and command delivery are split across incompatible implementations.**

- [Main HA WebSocket setup](v3_migration/backend/src/devices/managers/homeAssistantManager.js#L169-L294) marks `wsConnected` on transport open, sends auth and subscription immediately, and does not process `auth_ok`, `auth_invalid`, or subscription acknowledgement as connection-state transitions. Close/error handlers only log/broadcast; no automatic reconnect or application heartbeat is present in this manager. REST polling remains available, so this does **not** mean all automation stops instantly.
- Entity removal events (`new_state === null`) are ignored, leaving stale inventory. A failed bulk refresh preserves old state without a freshness classification, and `lastFetchTime` only advances on success: [v3_migration/backend/src/engine/nodes/HADeviceNodes.js](v3_migration/backend/src/engine/nodes/HADeviceNodes.js#L134-L211). Repeated ticks can retry immediately after failures instead of respecting backoff.
- Backend nodes bypass the main manager's health/retry/normalization logic through direct HTTP calls. Several command calls lack deadlines, and some edge state is advanced before success, suppressing another attempt when the input remains unchanged. A service acceptance response is not proof that the physical device reached the desired state.
- [v3_migration/backend/src/devices/managers/homeAssistantMediaPlayerManager.js](v3_migration/backend/src/devices/managers/homeAssistantMediaPlayerManager.js#L136-L157) constructs a **new manager for every exported call**. `getDevices()` reads a new empty instance; `shutdown()` cannot close the initialized instance's socket. This is a concrete ownership defect, not merely an objection to two sockets.
- Settings support updating credentials; do not invent a fixed HA token expiration interval or an automatic long-lived-token refresh mechanism. Treat 401/`auth_invalid` as reauthentication-required until valid credentials are supplied.
- **Fix:** one managed HA connection/cache boundary, subscribed/ready states, reconnect/backoff, freshness-aware normalized entities, a shared bounded command gateway, and consolidation/adaptation of the media manager. Preserve direct Hue/Kasa functionality.

**F09 — P1: observability can hide failures and grow files indefinitely during a long run.**

- [v3_migration/backend/src/engine/engineLogger.js](v3_migration/backend/src/engine/engineLogger.js#L135-L218) and [v3_migration/backend/src/engine/commandTracker.js](v3_migration/backend/src/engine/commandTracker.js#L51-L91) check rotation only when opening a stream, not while writing. The 10 MB/5 MB constants are not actual continuous-run caps. Stream errors/backpressure are not handled as a bounded operational state.
- Engine per-node exceptions are printed only in debug mode and leave prior outputs cached: [v3_migration/backend/src/engine/BackendEngine.js](v3_migration/backend/src/engine/BackendEngine.js#L482-L499). A failed sensor/calculation may appear healthy while downstream sees stale values.
- [Command attribution](v3_migration/backend/src/engine/commandTracker.js#L159-L190) calls temporal correlation “confirmed” without matching a unique command/context. Another automation or a manual action within ten seconds can be mislabeled.
- The log subscription handler expects `logger.on/off`, but [v3_migration/backend/src/logging/logger.js](v3_migration/backend/src/logging/logger.js) is not an event emitter. [The status route](v3_migration/backend/src/api/routes/engineRoutes.js#L57-L72) reads `status.startTime`; the engine returns `startedAt`. The resulting uptime calculation is invalid.
- **Fix:** bounded continuously rotated structured logs, error/backpressure handling, per-node error/freshness status, accurate command lifecycle/correlation, and tested status/event interfaces. Do not log every tick by default.

**F10 — P1: process survival is being mistaken for service health.**

- [v3_migration/backend/src/server.js](v3_migration/backend/src/server.js#L47-L98) installs an unconditional keep-alive and chooses to continue after uncaught exceptions/unhandled rejections. Duplicate fatal handlers appear at the end. Keeping a damaged process alive can prevent a supervisor from recovering it.
- Despite the comment, [shutdown handling](v3_migration/backend/src/server.js#L1442-L1501) registers `SIGINT`, not an explicit `SIGTERM` drain path. It does not coordinate stopping the engine, managers, camera workers, socket connections, or log streams. The add-on launcher uses `exec node`, so normal container termination needs an actual shutdown contract.
- [Startup](v3_migration/backend/src/server.js#L1376-L1416) waits for optional integrations/weather before opening the listener. The initial HA state request has no deadline. A slow optional dependency can hold startup behind a process that is still alive.
- **Fix:** explicit startup/readiness/degraded states, bounded optional initialization, shared idempotent shutdown, supervisor-friendly fatal exits, and health tied to completed work rather than a referenced timer. Preserve desktop launch expectations deliberately rather than indiscriminately deleting the old keep-alive workaround.

**F11 — P1: the add-on build is not reproducible and omits part of the intended architecture.**

- [home-assistant-addons/t2autotron/Dockerfile](home-assistant-addons/t2autotron/Dockerfile#L1-L40) clones a moving `stable` branch, uses `npm install`, and copies the backend and frontend but **not the sibling shared directory**. The shared route resolves that sibling directory: [v3_migration/backend/src/api/routes/sharedLogicRoutes.js](v3_migration/backend/src/api/routes/sharedLogicRoutes.js#L13-L24). Backend modules such as [v3_migration/backend/src/engine/nodes/LogicNodes.js](v3_migration/backend/src/engine/nodes/LogicNodes.js#L10-L17) fall back when it is absent; the image can therefore run without the very shared logic the architecture relies on.
- [.gitignore](.gitignore#L1-L5) excludes dependency lockfiles; local package locks exist but are not tracked by the parent. The Dockerfile provides no FFmpeg installation despite camera support being part of the backend. Camera capability must either be packaged or explicitly unavailable.
- Node 20 is the image base. It is EOL as of this review according to the [official Node release table](https://nodejs.org/en/about/previous-releases). Choose a supported runtime **after testing all declared CPU architectures**, especially `armv7`; do not silently drop 32-bit Pi users or assume all modern Node images support them.
- Metadata differs: development backend `2.1.240`, add-on config `2.1.242`, Docker build default `2.1.241`, image label `2.1.56`. This proves inconsistent metadata, not that the source versions differ by a known number of bug fixes.
- **Fix:** one immutable source revision per release, tracked locks, deterministic installation, complete artifact manifest including shared code, coherent version metadata, and built-image smoke tests. Do not “fix” production by editing only copied add-on backend files that this Dockerfile does not consume.

**F12 — P2: Pi resource policy is implicit and desktop-oriented.**

- [CameraService defaults](v3_migration/backend/src/cameras/CameraService.js#L34-L42) retain 150 full-resolution frames/camera at a default 30 fps, while [v3_migration/backend/src/cameras/FrameBuffer.js](v3_migration/backend/src/cameras/FrameBuffer.js#L9-L34) caps frame count, not bytes. This is bounded by count but can still consume substantial RAM; actual JPEG size and FFmpeg memory were not measured.
- Engine dependency sorting and edge scans repeat every tick: `gatherInputs()` is a full edge scan per node; graph work is roughly proportional to nodes × edges, plus all-Sender/all-Receiver virtual dependencies. Most topology is unchanged between ticks.
- **Fix:** cache the compiled order/inbound adjacency per graph revision; measure before event-driven redesign. Offer explicit camera-off/on-demand and FPS/history byte-budget profiles, with UI visibility and resource metrics. Preserve configured main-stream resolution; never silently substitute a substream or keyframe-only decoding.

**F13 — P2: plugin loading guarantees download order, not dependency readiness or successful registration.**

- Infrastructure does load sequentially; that is **not** the defect. [v3_migration/backend/plugins/00_SharedLogicLoader.js](v3_migration/backend/plugins/00_SharedLogicLoader.js#L34-L76) starts asynchronous module fetching without exposing an awaited readiness result, uses a separate non-ingress-aware base variable, and evaluates fetched code.
- [v3_migration/backend/plugins/TimeRangeNode.js](v3_migration/backend/plugins/TimeRangeNode.js#L38-L54) captures the shared function at script initialization, so slow loading can leave it on its fallback for the entire session. [PluginLoader](v3_migration/frontend/src/registries/PluginLoader.js#L137-L150) resolves on script load, not on registration; a script that returns early can be counted as loaded.
- **Fix:** explicit readiness/registration results, dependency metadata, shared ingress/auth URL helpers, versioned caching, and eventually loading trusted modules without `eval`. Do not claim external plugins are sandboxed; scripts currently execute with app-page privileges.

**F14 — P2: editor interaction and extension contracts are too entangled.**

- Large [v3_migration/frontend/src/Editor.jsx](v3_migration/frontend/src/Editor.jsx) mixes document model, rendering, execution, persistence, navigation, and interactions. Serializers are repeated across multiple paths; runtime state is often mixed into `properties`.
- Undo is a custom deletion stack, not a general transaction history: [v3_migration/frontend/src/Editor.jsx](v3_migration/frontend/src/Editor.jsx#L2107-L2246). The installed history package does not make property changes, moves, or wires undoable by itself. Right-click deletion also has its own path.
- [v3_migration/frontend/src/sockets.js](v3_migration/frontend/src/sockets.js) repeats compatibility rules in multiple monkey patches; its comments disagree with its actual `any`-to-boolean allowance. The frontend processor drops callbacks arriving during an active run rather than marking a follow-up run pending.
- **Fix:** extract document/command/history/serialization services behind the current editor; use one tested compatibility contract and queue a follow-up evaluation when changes arrive mid-run. Preserve existing accepted connection semantics until explicit migration decisions are made.

**F15 — P1: current green tests do not cover the failure boundaries that matter.**

- [v3_migration/backend/tests/apiSmoke.test.js](v3_migration/backend/tests/apiSmoke.test.js#L29-L50) mounts simulated routes, not production settings/engine routes. Its unauthorized test [accepts either 200 or 403](v3_migration/backend/tests/apiSmoke.test.js#L77-L89), so it cannot establish enforcement.
- Engine tests exercise simple ordering and synchronous stubs, not overlapping I/O, invalid activation rollback, timer cleanup, shutdown, HA reconnection, real node type identity, or nested execution. One test deliberately accepts skipped unknown node types.
- The existing [workflow](.github/workflows/ai-bug-triage.yml) triages issues; there is no tracked parent PR build/test gate in the inspected workflow directory. The frontend has build/lint scripts but no test script.
- **Fix:** production-module contract tests with fake HA/clock/transport, real route mounting in a side-effect-free app factory, browser persistence/ingress tests, and release artifact tests. Fix the five open timer handles instead of standardizing forced test exit.

## Recommended target architecture

**Keep a modular monolith.** No microservice rewrite, replacement graph editor, database migration, mandatory TypeScript conversion, or broker is justified by the evidence. Extract the following logical interfaces first; these names are proposed components, **not claims that new files already exist**.

| Boundary | Concrete contract and responsibility |
|---|---|
| `GraphDocumentCodec` | `decode(raw)` returns a normalized document and explicit migration diagnostics; `encode(document)` produces portable JSON. Treat unversioned existing formats as legacy version 0. Add integer `schemaVersion`, persistent `projectId`, revision, stable node `type` and `typeVersion`, serializable `properties`, consistent `{x,y}` positions, stable edge/port IDs, and viewport metadata. Application release version is separate from schema version. Preserve unknown node/property data for recovery. |
| `GraphValidator` / `GraphCompiler` | Validate shape, limits, types, IDs, ports, nesting, edge compatibility and cycles. Return structured diagnostics with node/port paths. Produce order, inbound-edge maps and buffer dependencies once per revision. Match actual buffer channels rather than connecting every sender to every receiver. Reject implicit feedback initially; support intentional feedback only through a separately specified state boundary, not arbitrary cycle breaking. |
| `GraphStore` | `load(projectId)`, `save(document, expectedRevision)`, and `loadLastGood()` behind the existing API. Serialized writers, atomic replacement and recovery copy; storage-root containment; `409` on stale revisions; separate durable saved revision from runtime active revision. Use the same root resolver for startup, handoff, named save, socket load, cameras, and recovery. Keep JSON rather than adding a database by default. |
| `ExecutionCoordinator` | Own compiled graph generation, one active tick, start/stop/activation barriers, cancellation and completion status. Compile before modifying live state; drain/fence old work before commit. Context includes `graphRevision`, `tickId`, injected clock, `AbortSignal`, and shadow/active phase. Emit lifecycle events; no method monkey-patching. |
| Node adapter contract | Stable type metadata, config validation/restore, evaluation, optional `start/stop/dispose`, declared ports and effect capabilities. Existing `data(inputs)` and `process(inputs)` can be adapted without rewriting all nodes. Keep input arrays and explicit distinctions among missing input, false, unavailable state, and failure. Separate persisted configuration from ephemeral caches/timers and optional versioned runtime checkpoints. |
| `OwnershipCoordinator` | Browser remains preferred, backend remains fallback, timeout remains 30 seconds. Every disconnect, explicit inactive, timeout, wake and reconnect uses one state transition. Capture owner/client identity and generation; acknowledge active graph revision before device-command authority changes. Multiple tabs must not independently act as simultaneous owners; document/select the controlling-tab policy before enabling it. A heartbeat interval below the timeout, e.g. 10 seconds, is a sender change—not a timeout change. |
| `DeviceCommandGateway` | All effect-producing backend nodes and browser-origin requests submit intent through one boundary. Intent carries graph revision, owner generation, node/entity/service/data and command kind. Record shadow intent even when transmission is suppressed. Distinguish intent, queued, sent, accepted, confirmed, failed and superseded. | `HaConnection` / `EntityStore` | REST bootstrap plus authenticated/subscribed WebSocket state machine, reconnect/backoff, heartbeat, snapshot resync, entity removal/capabilities, and fresh/stale/unavailable status. Publish normalized events to adapters/UI. Keep existing device-ID and brightness-scale helpers at the boundary. Reauthentication failure is explicit, not an infinite retry loop. |
| `EditorDocumentController` | Own the whole project independently of the currently displayed subgraph. Execute undoable changes, track dirty revisions, compose nested edits and serialize once. Existing Rete canvas becomes an adapter, not a second document authority. Expose save acknowledgement, conflicts, unsupported nodes, validation errors, and active owner/revision in the existing UI. |
| `RuntimeLifecycle` / diagnostics | Side-effect-free construction; explicit start and idempotent stop/dispose; optional workloads have resource/deadline limits. Health reports engine last completed tick, HA readiness/freshness, active/saved revisions, queue depth, memory and logging/storage degradation. Auth and log timers are owned and disposable. |

**Failure semantics to decide explicitly:** a node failure must not silently look like a valid new value. Do not convert missing/unavailable into `false` and turn devices off accidentally. Do not resume old queued commands after ownership or graph revision changes.

## Suggested implementation order

1. **Record baseline and contain exposure.** Preserve the dirty worktree, collect synthetic/redacted fixtures, capture the current 160-test result. Add failing W1 regressions and patch access/redaction/shell boundaries first. Temporarily disable unsafe direct exposure if a tested trust policy cannot be shipped immediately.
2. **Make releases testable.** Start W2: test factories and real route mounts without starting the product, track reviewed locks, prove the actual image contains shared logic. Select/pin a supported runtime only after architecture compatibility checks. Do not publish a version-only fix.
3. **Stop accepting wrong graphs.** W3: canonical codec, Watchdog identity, candidate validation and clear unsupported-node/subgraph diagnostics. Keep original bytes and old active graph on failure.
4. **Remove execution races.** W4: single-flight scheduler, activation serialization, old-generation fences, node timer cleanup, proper asynchronous start and shutdown. Temporary command gating during activation is safer than half-running two graphs.
5. **Enforce one owner; repair HA recovery.** W5/W6 in small connected PRs: normalize state/command contracts, inventory all effect nodes, add final-dispatch ownership checks, then reconnect/freshness/backoff and safe handoff. Retain browser-first behavior throughout.
6. **Make saves authoritative and honest.** W7: atomic store, root document, expected revisions, server acknowledgement, authenticated ingress-aware client, no close-only dependency. Test empty/large graphs and nested navigation before changing UI affordances.
7. **Make failures visible and bounded.** Finish W8 log/status/support tooling. Run failure injection and a real Pi soak before promoting the release.
8. **Complete missing features rather than masking them.** W9 nested execution and plugin readiness; W10 Pi profiles, command-history UX, editor extraction, full undo/redo. Evaluate further features only against measured resource headroom.

Every PR should state its work-package ID, behavioral change, tests, compatibility impact, migration/rollback procedure, and unresolved risks. Avoid a single branch that attempts all ten packages simultaneously.

## Constraints the implementer must not break

1. **Browser controls while active; backend shadows and takes over after inactivity.** Preserve the 30-second heartbeat timeout, frontend state tracking, manual changes, and immediate HSV resynchronization after safe handoff. Fix enforcement; do not invert this design.
2. **HSV-only updates must not wake an OFF light.** Unknown/stale device state must not be assumed ON. Intent, observed state, and last successful command are different facts.
3. Preserve `ha_`, `hue_`, `kasa_` and other established identifiers using existing normalization helpers. Keep UI brightness 0–100, HA command brightness 0–255, Hue native 0–254, and existing normalized HSV conventions explicit. Do not infer every value's scale from whether it is below 1.
4. Preserve pass-through/latching delay behavior and explicit pulse-node behavior. Keep `undefined` distinct from `false`; “no value yet” does not mean “turn off.” Preserve input-array semantics and supported socket compatibility while migrating.
5. Support old saved formats through migrations, not silent drops or permanent fallback guessing. Preserve original documents, unknown node payloads, nested data, custom titles, positions and viewport. Keep the old active graph on validation/activation failure.
6. Keep plugins in the backend plugin system, with browser adapters separate from backend execution and shared pure logic. Do not move node creation into deprecated frontend node directories. Preserve direct `RefComponent` socket rendering and pointer propagation.
7. Treat [v3_migration/frontend/src/Editor.jsx](v3_migration/frontend/src/Editor.jsx) as protected: add regression tests, extract small responsibilities, and avoid wholesale rewrite. Do not call `changeCallback()` inside `data()` or break callback cleanup/chaining.
8. HA ingress, authenticated direct access, desktop/browser/Electron, and supported Pi architectures must remain explicit deployment modes. HA add-ons must not start running git-based in-app updates.
9. Preserve configured camera main streams. No secret substream substitution, no keyframe-only live decoding, and no default requirement for NVIDIA hardware or local GPU TTS on a Pi. Optional-feature resource reductions must be visible/configurable.
10. No live Home Assistant/device actions in unit/CI tests. Use mocks or dedicated test devices only with explicit authorization. Never log tokens, PINs, camera passwords, or credential-bearing URLs; support bundles must redact them.
11. Respect the user's running server and pre-existing worktree. Do not start/stop it, rewrite saved user graphs, broadly clean directories, or commit unrelated changes. Source and add-on releases require deliberate staging, testing, version/changelog synchronization, add-on push first when changed, then parent-reference publication according to project rules.
12. This task authorizes **review and handoff only**. Implementation, release commits, server changes, and pinned future features need a subsequent request.

## Handoff brief for a cheaper coding model

**Mission:** implement one work package at a time from this document after receiving authorization. Strengthen the existing CommonJS backend/ESM frontend/plugin architecture; do not invent a new app.

**Read first, in this order:** the relevant findings and constraints above; [v3_migration/backend/src/engine/BackendEngine.js](v3_migration/backend/src/engine/BackendEngine.js); [v3_migration/backend/src/api/engineSocketHandlers.js](v3_migration/backend/src/api/engineSocketHandlers.js); [v3_migration/backend/src/api/routes/engineRoutes.js](v3_migration/backend/src/api/routes/engineRoutes.js); then the work-package files listed above. Use this call-flow map rather than rediscovering everything:

1. Browser registry creates plugin node → editor serializes it → save endpoint persists it → backend registry resolves/instantiates it → engine restores properties.
2. Engine tick orders nodes → gathers arrays of upstream values → awaits `data()`/`process()` → stores outputs → effect node currently may call HA directly.
3. Browser active/heartbeat/inactive → server's `activeEditors` set → engine ownership state → device command suppression. **This is the intended policy, not a bug to remove.**
4. HA REST snapshot/WebSocket event → manager's normalized device updates → Socket.IO/plugin UI. Separately, backend HA nodes currently poll `bulkStateCache`; unify freshness gradually.
5. Add-on build → clone pinned replacement for current moving stable ref → build canonical frontend/backend/shared artifacts → launch with durable `/data` storage. Do not patch only the unused copied backend tree.

**Known traps, already verified:**

- The generic backend node has no instance `type`; the current resync filters miss it. Its configured entities are `selectedDeviceIds`, not `devices`. HA `getState()` returns an envelope, not a raw state.
- `shouldSkipDeviceCommands()` currently performs a state mutation on timeout without the handoff sequence. Do not merely sprinkle more callers of this method around the code.
- `engine.start()` is replaced by a non-awaiting socket wrapper; fixing the original async method alone is insufficient.
- Stopping the interval does not stop an in-progress promise; timeout-racing a promise without fencing/cancelling its eventual effects is also insufficient.
- Node restore can start timers. Preparing a candidate graph must not leak timers or issue device effects before activation.
- Upcoming-event registry entries are display metadata. Old node timers are the separate cleanup problem.
- Main load/import **already validate/repair**. Plugin infrastructure **already loads sequentially**. Address the actual gaps, not the opposite claims.
- Both subgraph executors contain real TODOs. Do not “fix” them by returning a success object or treating grouping as execution.
- Graph saves must compose the root, not serialize the viewed subgraph. Empty documents and large documents need real server persistence.
- Locks are locally present but ignored/untracked. The image currently omits shared code and uses fallbacks. Do not infer correctness from a successful frontend build alone.
- The green API smoke test permits unauthorized success. Green tests need stronger assertions and production-module coverage.

**Small-PR procedure:**

1. Inspect `git status` and preserve unrelated modifications. Confirm cited code is still current; line numbers are review-time anchors.
2. Select one W-package and list the exact acceptance cases it will satisfy. Add a failing test against the real module with a fake HA transport/clock/storage.
3. Make the smallest compatible extraction/fix. Prefer existing libraries already used by the project; add dependencies only with a reason and lockfile update.
4. Run relevant backend tests, frontend build/tests where affected, and artifact checks for packaging changes. Record commands/results and open limitations. Never solve tests by making live device requests, disabling auth, removing safety checks, or accepting both success and failure.
5. Update this document only if verified architecture facts change. Provide a short plain-English explanation, migration notes and rollback steps. Do not change release versions or publish unless asked.

**Suggested first implementation assignment:** W1, with separate regression-tested commits for ingress/direct authentication plus camera redaction, then shell-free configuration/snapshot handling. In parallel planning—not concurrent edits to the same files—prepare W2's isolated test factories. After security containment, W3/W4 are the best reliability investment.

**Stop and ask rather than guess** if a proposal changes the 30-second timeout/browser priority, drops a Pi architecture, changes pulse/manual override semantics, migrates private real graphs, starts a live server, or expands the pinned camera/vision/TTS feature scope.
